# BookScan V4 · 自动裁边优先版

## 更新
1. 先导出已有 PDF、备份跨页原图。不要清除 Safari 网站数据。
2. Windows 解压 ZIP，将内部全部 10 个文件上传至现有 `welgume-cpu/BookScan` GitHub 仓库的 main 根目录并覆盖同名文件，点击 Commit changes。
3. GitHub Pages 部署成功后，使用 iPad Safari 打开原网址。刷新或关闭重开，确认顶部显示「v4 自动裁边优先」。旧版首次升级会自动切换为自动裁边模式。数据库名称保持不变；仍需备份，不能保证 Safari 永久保留数据。

## 自动扫描流程（无需手动拖四角）
- iPad 固定在书上方，相机尽量与桌面平行。书下铺无反光深灰/黑色桌垫；确保完整书本的四边都在画面内，与画面边缘留出间距，周围不要放杂物。光线均匀。
- 开启摄像头 → 开启自动拍摄。程序用多阈值分割、连通区域、四边独立稳健直线拟合和四边内外亮度差验证估计书本轮廓，而不是把全图裁去固定比例。黄色轮廓表示还在确认；绿色表示连续两次检测位置接近。
- 画面稳定且四边确认后才触发拍摄。正式采集的图像重新识别边缘，并与预览结果比对；通过后做平面透视裁切及左右分割，原始照片与结果一同保存在设备本地。看到「已保存…可以翻页」后才翻页。
- 失败时自动拍摄不计入成功页；程序会等待并重试。请保持当前书页或调整光线、书本位置，不要继续翻页。这样做是为了避免默默漏页或把桌面作为书页。仍不能保证发现用户快速翻过的所有页面。
- 手动校准、固定角和传统比例模式只是高级可选项；不属于默认自动扫描流程。当前书脊仍按设置比例分割（默认50%），不是自动检测书脊或曲面展开。

## 旧扫描结果 / 导入照片
- 点「重新裁边全部」：自动逐组重新识别全部原图；成功的组更新裁边并清除旧 OCR，失败的组保留原图及旧结果并标为未通过；其他组继续处理。请按需重新 OCR，原有人工校对也可能被清除。
- 导入照片若识别失败，会保留原图作为待处理项，不计入可用页数；失败项存在时禁止导出整书 PDF，防止无提示漏页。可以等待重处理、重新拍摄并删除失败项，或使用可选的手动修正。
- 原图永远不因裁边被覆盖。旧版本的成功标记并不代表已通过 V4 检验，建议统一重新裁边。

## 全书搜索与 PDF
保留 V3 的本地 OCR 和关键词搜索。选择识别语言后点击识别未处理书页，首次需网络下载 Tesseract.js 和语言包。不向 OCR 服务器上传照片。未通过裁边的组不参与 OCR。PDF 仍是图片型，不带可搜索文字层。

## 验证与局限
已通过 JavaScript 语法检查；用 8 个合成场景测试检测函数（5 个有效场景：平放、透视、旋转、书脊阴影、独立干扰物；3 个拒绝场景：低对比度、边缘出画、无书页）。5 个有效场景角点最大归一化误差均小于 2.5%，3 个拒绝场景均返回无有效边缘。这不是实际书本的准确率。浏览器端到端测试因运行环境阻止 localhost 导航而未能执行，尚未在 iPad Safari 实机验证。
对浅色桌面、强反光、严重弯曲书页、背景与书页相近、书页边缘遮挡等，本算法仍可能误判或拒拍。请先连续扫描 10–20 组跨页确认质量，再扫描整书。厚书曲面矫正、自动书脊定位、全书实际漏页核验、画质评分尚未实现。
